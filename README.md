# cars-zeekr

Сайт автосалона (MVP). Стек: **FastAPI · PostgreSQL · Redis · MinIO · React + TypeScript (Vite)**, всё в Docker Compose.

Документы: [ТЗ](docs/tz-autosalon.pdf) · [план MVP](PLAN.md) · [дизайн-система](docs/design/DESIGN.md).

## Быстрый старт

Требуется Docker + Docker Compose.

```bash
cp .env.example .env        # при необходимости поменяйте значения
docker compose up -d --build
```

Сервисы:

| Сервис | URL | Назначение |
|--------|-----|-----------|
| API (FastAPI) | http://localhost:8000 | REST API, Swagger на `/docs` |
| Frontend (Vite) | http://localhost:5173 | веб-интерфейс |
| Админка (SQLAdmin) | http://localhost:8000/admin | CRUD каталога (см. [ниже](#админка-sqladmin)) |
| MinIO Console | http://localhost:9001 | S3-хранилище (логин/пароль из `.env`) |
| PostgreSQL | localhost:5432 | база данных |
| Redis | localhost:6379 | кэш / очереди |

Проверка здоровья:

```bash
curl http://localhost:8000/health         # {"status":"ok"}
curl http://localhost:8000/health/ready    # проверяет доступность БД и Redis
```

Остановить:

```bash
docker compose down          # + флаг -v чтобы удалить тома с данными
```

## Переменные окружения

Все ключи перечислены в [`.env.example`](.env.example) — скопируйте его в `.env` и при необходимости поменяйте. Группы:

| Группа | Ключи | Назначение |
|--------|-------|-----------|
| Окружение | `APP_ENV` | режим (`dev` / прод-валидация секретов) |
| Инфраструктура | `DATABASE_URL`, `REDIS_URL`, `S3_ENDPOINT` (in-cluster), `S3_PUBLIC_ENDPOINT` (для браузера), `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_BUCKET` | подключения к Postgres / Redis / MinIO |
| CORS | `CORS_ORIGINS` | origin'ы фронтенда (через запятую) |
| Auth / JWT | `JWT_SECRET`, `JWT_ALGORITHM`, `ACCESS_TOKEN_TTL_MIN`, `REFRESH_TOKEN_TTL_DAYS`, `LOGIN_RATE_*` | токены и анти-брутфорс логина |
| Админка | `ADMIN_EMAIL`, `ADMIN_PASSWORD` | учётка панели `/admin` (см. ниже) |
| Заявки | `LEADS_RATE_*`, `TRUST_PROXY`, `TELEGRAM_*` | анти-спам и Telegram-уведомления |
| Frontend | `VITE_API_URL` | адрес API для браузера |
| Карты | `VITE_YANDEX_MAPS_API_KEY` | ключ Яндекс Карт для блока с точками на главной (см. ниже) |

> При `APP_ENV != dev` приложение **не стартует** с дефолтным `JWT_SECRET` — задайте свой секрет в проде.

## Яндекс Карты на главной

Блок «Контакты на карте» на главной показывает точки дилеров (раздел админки
«Точки на карте») на интерактивной Яндекс Карте. Без ключа или без точек
показывается статичная контактная карточка (фоллбэк) — страница не падает.

**Как включить карту:**

1. Получите ключ в [кабинете разработчика Яндекс](https://developer.tech.yandex.ru/services/).
   Тип ключа — **«JavaScript API»** (важно: ключи Геокодера / Static API эндпоинт
   v3 не примет — будет `403 Invalid api key`).
2. В настройках ключа добавьте `localhost` в **разрешённые referer** (поле
   «Ограничение по HTTP Referer», без протокола и порта). Для прода — ваш домен.
3. Пропишите ключ в корневом `.env`:
   ```
   VITE_YANDEX_MAPS_API_KEY=ваш-ключ
   ```
4. Пересоздайте web-сервис, чтобы Vite подхватил ключ:
   ```
   docker compose up -d --force-recreate web
   ```
5. Откройте http://localhost:5173 и обновите страницу жёстко (Ctrl+Shift+R).

**Проверка ключа:** откройте в браузере
`https://api-maps.yandex.ru/v3/?apikey=ВАШ_КЛЮЧ&lang=ru_RU` — рабочий ключ
отдаёт JavaScript-код, нерабочий — `{"statusCode":403,"message":"Invalid api key"}`.

## Миграции (Alembic)

Миграции применяются автоматически при старте `api` (entrypoint выполняет `alembic upgrade head`).
Вручную, внутри контейнера:

```bash
docker compose exec api alembic upgrade head            # применить
docker compose exec api alembic revision --autogenerate -m "описание"   # создать новую (после правки моделей)
docker compose exec api alembic downgrade -1            # откатить
```

URL базы берётся из настроек приложения (`DATABASE_URL`), в `alembic.ini` он пустой — секретов в репозитории нет.

## Демо-данные (seed)

Наполнить каталог демо-данными Zeekr (бренд, модели 001/7/X/009, комплектации, цвета,
плейсхолдер-изображения в MinIO). Скрипт идемпотентный — повторный запуск не дублирует:

```bash
docker compose exec api python -m app.seed
```

## API каталога

`GET /cars` — список с фильтрами, пагинацией и сортировкой; ответ кэшируется в Redis.

| Параметр | Описание |
|----------|----------|
| `brand`, `model`, `body_type`, `engine_type` | slug справочника |
| `transmission`, `drive` | slug (по комплектациям машины) |
| `condition` | `new` / `used` |
| `year_min`, `year_max`, `price_min`, `price_max`, `mileage_max` | диапазоны |
| `sort` | `newest` (по умолч.), `price_asc`, `price_desc`, `year_desc` |
| `page`, `page_size` | пагинация (`page_size` ≤ 60) |

`GET /cars/count` — счётчик «Найдено N» для блока быстрого подбора (те же фильтры).

`GET /cars/{slug}` — детальная карточка: галерея, комплектации (с КПП/приводом),
характеристики, цвета, подарки и блок «похожих предложений» (тот же кузов, затем
ближайшие по цене). `404`, если slug не найден.

Кэш версионируется ключом `catalog:version`; любое изменение каталога (seed,
правки в [админке](#админка-sqladmin)) вызывает `bump_catalog_version()` и разом
инвалидирует выборки.

## Профиль и заявки

Публичные заявки доступны только авторизованным пользователям. Если гость
нажимает «Купить» или «Забронировать» (в каталоге, на карточке авто или
запчасти), фронтенд сначала предлагает войти или зарегистрироваться.

`POST /leads` — создание заявки текущего пользователя (JWT в
`Authorization: Bearer ...`). Заявка хранит источник (`source_title`), авто
(`car_id`, опц.), комментарий с деталями формы и ключ дедупликации
(`dedupe_key`).

- Телефон нормализуется к `+7XXXXXXXXXX`; согласие (`consent`) обязательно.
- Активные повторы блокируются серверно по `user_id + dedupe_key`: повторный
  клик возвращает существующую заявку, а не создаёт дубль.
- Анти-спам по IP остаётся включённым через Redis
  (`LEADS_RATE_LIMIT`/`LEADS_RATE_WINDOW`), honeypot `company` сохраняет
  поведение «успех без записи» для ботов.
- Заявка сохраняется в БД и уходит уведомлением в Telegram-бот
  (`TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID`; без них — тихо пропускается).

Профиль пользователя:

- `PATCH /profile` — изменить имя и телефон.
- `POST /profile/password` — сменить пароль (текущий пароль + новый).
- `GET /profile/leads` — список своих заявок со статусом и авто. Статусы заявок
  (в обработке / одобрено / отклонено и т.д.) выставляет админ в SQLAdmin;
  предоплата и оплата на сайте не происходят.

## Аутентификация

Регистрация нужна для публичных заявок и личного кабинета. JWT access/refresh,
пароли хешируются argon2.

- `POST /auth/register` — регистрация: `email`, `password`, `full_name`,
  `phone`. E-mail на `@gmail.com`/`@googlemail.com` отклоняется:
  `451 Unavailable For Legal Reasons`, тело
  `{"detail": {"code": "GMAIL_FORBIDDEN", "message": "…"}}`.
- `POST /auth/login` — выдаёт `access_token`/`refresh_token` (rate-limit по IP).
- `POST /auth/refresh` — новый access по refresh-токену.
- `GET /auth/me` — текущий пользователь (заголовок `Authorization: Bearer …`).

На фронтенде форма регистрации требует имя, телефон, e-mail, пароль и
подтверждение пароля. Вход/регистрация открываются из шапки и из CTA, которые
требуют аккаунт.

Тесты: `cd backend && pytest` (in-memory SQLite, Redis застаблен).

## Админка (SQLAdmin)

Панель управления каталогом: **http://localhost:8000/admin**.

Доступ — учётка с флагом `is_admin` (та же таблица `user_account` и argon2-хэши,
что и в публичной авторизации). Админ создаётся/повышается при старте `api` из
`ADMIN_EMAIL`/`ADMIN_PASSWORD` (пустой пароль — создание пропускается; пароль
существующего админа не перезаписывается — меняйте в самой панели). Вход — по
e-mail и паролю.

Возможности:

- **Каталог → Авто** — одна форма на автомобиль: всё содержимое карточки
  (герой, цвета, комплектации, преимущества, подарки, характеристики, фото) плюс
  видимость на сайте (`is_hidden`). Созданное авто сразу публикуется. Список —
  простая таблица с действиями «Редактировать / Скрыть-Показать / Удалить». См.
  гайд: [docs/card-composer.md](docs/card-composer.md).
- **Заявки → Заявки** — все обращения пользователей: имя, телефон, источник,
  авто, статус и комментарий. Админ переводит заявку в `approved`/`rejected`
  (и др. статусы); в личном кабинете пользователь видит текущий статус. Оплата и
  предоплата на сайте не происходят.
- **Каталог → Запчасти** — отдельная форма запчасти (название, категория,
  совместимая марка, состояние, оригинал/аналог, производитель, артикул, цена,
  описание, фото), по образцу формы авто, но без привязки к автомобилю.
- **Справочники** — бренды, модели, типы кузова / КПП / привода / двигателя,
  цвета, категории запчастей.

Любое изменение инвалидирует кэш каталога — публичный API сразу отдаёт свежие данные.

## Запчасти

Независимый раздел «Запчасти» (`/parts`) построен по образцу «Авто с пробегом»:
панель марок, быстрый подбор, фильтры (категория, состояние, оригинал/аналог,
производитель, цена) и карточка запчасти. Деталь `/part/:slug` показывает
галерею, характеристики, описание и блок «Похожие предложения» — тоже запчасти.

- `GET /parts` — листинг с фильтрами и пагинацией (Redis-кэш).
- `GET /parts/filters` — опции фильтров (категории, марки, производители).
- `GET /parts/{slug}` — деталь запчасти + похожие.

## Фронтенд (страницы)

React + TS (Vite), маршрутизация на `react-router`. Реализовано:

| Маршрут | Страница |
|---------|----------|
| `/` | Главная — блок быстрого подбора «Я ищу» |
| `/catalog` | Каталог: сетка карточек, сайдбар брендов, фильтры (модель, кузов, КПП, привод, двигатель, цена-слайдер 0–3 млн, год/пробег для used), сортировка, «Показать ещё»; состояние фильтров в URL |
| `/catalog?condition=used` | Тот же каталог, отфильтрованный «с пробегом» (пункт «Авто с пробегом») |
| `/used` | Каталог авто с пробегом |
| `/special` | Каталог спецпредложений |
| `/parts` | Запчасти: панель марок, фильтры (категория, состояние, оригинал/аналог, производитель, цена), карточки |
| `/part/:slug` | Детальная карточка запчасти: галерея, характеристики, описание, похожие запчасти |
| `/credit` | Редирект на `/parts` (раздел «Кредит и рассрочка» заменён «Запчастями») |
| `/select` | Подборки автомобилей из админки |
| `/about` | О компании |
| `/contacts` | Контакты |
| `/search` | Поиск по каталогу |
| `/profile` | Личный кабинет: данные, смена пароля, заявки со статусами |
| `/car/:slug` | Детальная карточка: галерея, комплектации, характеристики, цвета, подарки, похожие |
| `*` | 404 (NotFound) |

## Архитектура

Монорепо: **backend** (FastAPI, async SQLAlchemy + Alembic, кэш в Redis, медиа в
S3/MinIO) и **frontend** (React + TS на Vite) поднимаются одним `docker compose`.
API отдаёт публичный каталог (авто и запчасти) и принимает заявки; админка
(SQLAdmin) смонтирована в то же приложение на `/admin`. Кэш каталога
версионируется в Redis и сбрасывается при любых изменениях данных.

```
backend/    FastAPI-приложение (app/), Dockerfile
  app/api/        REST-роутеры (catalog, parts, auth, profile, leads, health)
  app/admin/      SQLAdmin: модельные вьюхи + авторизация
  app/models/     ORM-модели (каталог, запчасти, пользователи, заявки)
  app/core/       конфиг, безопасность, кэш, хранилище, Telegram
frontend/   React + TS (Vite), Dockerfile.dev
docs/       ТЗ и дизайн-материалы
docker-compose.yml
```

## Ветки

- `prod` — стабильная (default).
- `dev` — рабочая; задачи делаются в feature-ветках `feat/...` → PR в `dev`.
